# Pika Park (피카파크) v1

포켓몬 디스코드 커뮤니티용 실시간 협동 퍼즐 플랫폼 게임입니다.
GitHub Pages(정적 호스팅) + Firebase Realtime Database(실시간 동기화)만으로 동작합니다.

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 시작 화면·대기실·게임 화면·결과/메뉴 모달 구조, CDN 로드 |
| `config.js` | **Firebase 설정값만 들어 있는 파일.** 한 번 입력해 두면 game.js를 새 버전으로 바꿔도 다시 입력할 필요 없음 |
| `style.css` | 픽셀 UI, 반응형 레이아웃, 모바일 가상 버튼, 모달·토스트 |
| `game.js` | 픽셀 아트 생성, 스테이지 데이터 10개, 물리·충돌, Firebase 동기화, 방장 진행 로직, HUD |
| `database.rules.json` | Realtime Database 보안 규칙 (콘솔에 붙여 넣는 설정 파일, 게임 소스 아님) |

이미지·효과음 파일은 없습니다. 피카츄와 모든 타일은 `game.js`에서 Canvas로 직접 그린 16×16 픽셀 아트입니다(공식 에셋 미사용).
나중에 스프라이트 이미지로 바꾸려면 `drawPika()`만 교체하면 됩니다.

외부 라이브러리 (버전 고정, 2026-10-15 CDN 존재 확인)
- Phaser 3.90.0 — `cdnjs.cloudflare.com/ajax/libs/phaser/3.90.0/phaser.min.js`
- Firebase JS SDK 12.19.0 compat (app / auth / database) — `www.gstatic.com/firebasejs/12.19.0/…`
- Galmuri 2.40.3 (한글 픽셀 폰트, SIL OFL) — `cdn.jsdelivr.net/npm/galmuri@2.40.3`

## 2. 구조 설계

### 동기화 방식
- **각자 자기 캐릭터만 물리 계산**하고 위치를 문자열 한 줄(`p`)로 보냅니다. 전송 간격 150~250ms(인원이 많을수록 길게), 변화가 없으면 보내지 않음.
- 다른 플레이어는 받은 위치를 **보간(데드 레커닝 + 부드러운 추적)**해서 매 프레임 그립니다. 렌더 주기와 전송 주기는 분리되어 있습니다.
- 누군가의 머리 위나 발판 위에 서 있으면 "누구 위에, 몇 px 옆에"를 함께 보내서, 모든 화면에서 탑이 어긋나지 않고 붙어 보입니다.
- **움직이는 발판·톱니는 서버 시간 기준 공식**으로 위치가 정해져서 동기화 트래픽이 0입니다.
- 스위치·문 상태는 저장하지 않고, 각 플레이어가 보낸 "밟고 있는 스위치" 값으로 모든 클라이언트가 같은 계산을 합니다(중복 저장 없음).
- 열쇠·체크포인트·무너지는 블록처럼 **동시에 여러 명이 건드릴 수 있는 상태는 트랜잭션**으로 바꿉니다.
- 클리어·다음 스테이지·재도전은 **방장만** `game`을 트랜잭션으로 바꿉니다. 스테이지마다 `seq`(세션 번호)가 올라가고 퍼즐 상태는 `puzzle/s{seq}` 아래에 있어서, 지난 스테이지의 늦은 이벤트가 새 스테이지를 덮어쓰지 못합니다.

### Firebase 데이터 구조
```
roomIndex/{코드}            마지막 활동 시각(오래된 방 정리용)
rooms/{코드}/
  info      { host, createdAt, lastActive }
  slots/{0~19}  uid         ← 자리 = 색상·번호. 규칙이 20자리만 허용 → 최대 20명 보장
  players/{uid} { name, slot, joinedAt, online, seen, tab }
  pos/{uid}     { p: "x,y,vx,vy,anim,flags,받침,오프셋,스위치", s: seq }
  game      { status: lobby|playing|cleared|finished, stage, seq, sk, startAt, runStartAt, clearedAt, n, times }
  puzzle/s{seq}/ { key, cp, cr/{블록id} }
```
- 플레이어 식별: **Firebase 익명 로그인 uid**(닉네임 아님). 같은 브라우저로 새로고침하면 같은 uid라 자동 복귀합니다.
- 접속 상태: `.info/connected` + `onDisconnect()`로 `online:false, seen` 기록.
- 같은 계정이 두 탭에서 들어오면 나중 탭이 `tab` 값을 바꾸고, 이전 탭은 스스로 멈춥니다(중복 참가 방지).

### 운영진(관리자)과 방장
- **운영진**: 구글 계정으로 로그인하고 Firebase 콘솔의 `admins`에 등록된 계정. 방 만들기, 게임 시작, 다음 스테이지, 재도전, 대기실 복귀를 할 수 있습니다. 일반 참가자는 로그인 없이(익명) 방 코드로 참가만 합니다.
- 화면에서 버튼을 숨기는 것만이 아니라 **보안 규칙이 서버에서 다시 검사**하므로, 일반 참가자가 코드를 조작해도 방을 만들거나 게임을 진행할 수 없습니다.
- **방장(host)**은 자동 관리 담당입니다: 끊긴 플레이어 정리, "모두 출구에 들어감" 판정. 방을 만든 운영진이 방장이 되고, 방장이 끊기면 남은 사람이 자동으로 넘겨받습니다. 일반 참가자가 방장이 되어도 할 수 있는 진행 변경은 "플레이 중 → 클리어"뿐입니다(규칙으로 제한).
- 같은 방에 운영진이 여러 명 있으면 누구나 진행할 수 있고, 트랜잭션 덕분에 동시에 눌러도 한 번만 반영됩니다.

### 방 정책
- 진행 중인 방: **새 참가 불가**(관전 모드 없음). 기존 참가자의 재접속은 허용. 운영진이 대기실로 돌아오면 참가 가능.
- 방장 이탈: 6초 이상 끊기면 남은 사람 중 번호가 가장 낮은 사람이 방장(자동 관리)을 넘겨받음. 다음 스테이지 진행은 운영진이 다시 들어와야 가능.
- 90초 이상 끊긴 플레이어는 방장이 정리(자리 반납). 마지막 사람이 나가면 방 삭제. 6시간 활동 없는 방은 다음 방 생성 때 정리.

## 3. Firebase 설정 (처음부터)

1. https://console.firebase.google.com 에서 **프로젝트 추가** → 이름 입력(예: `pika-park`) → Google 애널리틱스는 꺼도 됩니다. 요금제는 기본 **Spark(무료)**.
2. 왼쪽 메뉴 **빌드 > Authentication > 시작하기 > 로그인 방법**에서 두 가지를 사용 설정:
   - **익명** → 사용 설정 → 저장 (일반 참가자용)
   - **Google** → 사용 설정 → 프로젝트 지원 이메일 선택 → 저장 (운영진용)
3. **빌드 > Realtime Database > 데이터베이스 만들기** → 위치 선택(예: `asia-southeast1` 싱가포르) → **잠금 모드**로 시작.
4. Realtime Database의 **규칙** 탭 → 내용을 모두 지우고 `database.rules.json` 내용을 붙여 넣기 → **게시**.
5. **프로젝트 설정(톱니바퀴) > 일반 > 내 앱 > 웹(</>)** → 앱 닉네임 입력 → 등록(Hosting 체크 불필요).
6. 화면에 나온 `firebaseConfig` 값을 **`config.js`** 의 `window.PIKA_FIREBASE_CONFIG`에 넣기:
   ```js
   window.PIKA_FIREBASE_CONFIG = {
     apiKey: "…",            // 콘솔 값 그대로
     authDomain: "…",
     databaseURL: "https://…firebasedatabase.app",  // Realtime Database 화면 상단 주소와 같아야 함
     projectId: "…",
     appId: "…"
   };
   ```
   `databaseURL`이 설정 화면에 없으면 Realtime Database 데이터 탭 맨 위의 주소를 복사하세요.
   이 값들은 공개되어도 되는 클라이언트 식별값입니다. **서비스 계정 키·데이터베이스 비밀값은 절대 넣지 마세요.**
7. **Authentication > 설정 > 승인된 도메인**에 `내아이디.github.io`를 추가 (안 하면 운영진 구글 로그인이 실패합니다).
8. **운영진 등록** (배포 후, 운영진마다 한 번):
   1. 게임 사이트 시작 화면 맨 아래 **운영진 로그인** → 구글 계정 선택.
   2. "운영진으로 등록되지 않은 계정이에요"와 함께 **내 ID**가 보이면 **ID 복사**.
   3. Firebase 콘솔 **Realtime Database > 데이터** 탭 → 맨 위 경로 옆 **+** → 키 `admins` 추가 → 그 아래에 키 = 복사한 ID, 값 = `true`(불리언) 추가.
      결과 모양: `admins / Abc123…xyz : true`
   4. 게임 화면으로 돌아오면 바로 "운영진으로 로그인됨"으로 바뀌고 **방 만들기** 버튼이 생깁니다(새로고침 불필요).
   - 운영진 해제: 콘솔에서 해당 ID 항목 삭제.
   - 같은 구글 계정이면 PC·폰 어디서 로그인해도 같은 ID라 한 번만 등록하면 됩니다.

## 4. GitHub Pages 배포

1. GitHub 로그인 → 오른쪽 위 **+ > New repository** → 이름 `pika-park` → **Public** → Create.
2. **Add file > Upload files** → `index.html`, `style.css`, `game.js`, `config.js` 네 파일을 끌어다 놓기 → **Commit changes**.
   (`README.md`, `database.rules.json`도 올려도 무방합니다. 규칙 파일은 공개돼도 문제없습니다.)
3. 업로드한 `config.js`의 Firebase 설정값이 자리표시자(`YOUR_…`)가 아닌지 확인.
   - **나중에 코드를 업데이트할 때는 `game.js`(바뀐 파일만)만 다시 올리면 됩니다.** `config.js`는 건드리지 마세요.
   - 새 버전 `game.js`를 올린 뒤 화면이 그대로면 브라우저 강력 새로고침(Ctrl+Shift+R)을 해 주세요. GitHub Pages 캐시 때문에 몇 분 걸릴 수 있습니다.
4. 저장소 **Settings > Pages** → Source: **Deploy from a branch** → Branch: `main` / `(root)` → Save.
5. 1~2분 뒤 같은 화면에 나오는 주소(`https://내아이디.github.io/pika-park/`) 접속.
6. **F12 > Console**에서 빨간 오류가 없는지 확인. `[PikaPark] 로그인 완료`가 보이면 정상입니다.
   - "Firebase 설정이 필요해요" → `config.js`가 업로드됐는지, 값이 바뀌었는지 확인
   - 운영진 로그인 시 "승인된 도메인" 안내 → 3장 7번
   - `auth/operation-not-allowed` → 익명 로그인 미사용
   - `PERMISSION_DENIED` 반복 → 규칙 게시 여부 확인

방 코드 공유: 대기실 주소창 URL(`…/?room=ABCDE`)을 디스코드에 붙여 넣으면 코드가 자동 입력됩니다.

## 5. 멀티플레이 테스트 방법

> 아래는 **직접 해 보셔야 하는 점검표**입니다. 저는 Firebase/브라우저 환경에서 실제 멀티플레이를 실행해 보지 않았습니다(자세한 내용은 7장).

| # | 테스트 | 방법 | 기대 결과 |
|---|---|---|---|
| 0 | 운영진 권한 | 운영진 로그인 전/후 시작 화면 비교. 등록 안 된 구글 계정으로도 로그인해 보기 | 등록된 계정만 "방 만들기" 보임, 미등록 계정은 ID 안내 |
| 1 | 2인 방 생성·참가 | 크롬 일반 창에서 운영진 로그인 후 방 만들기 → **다른 브라우저**(엣지/파이어폭스) 또는 크롬 시크릿 창에서 코드로 참가 | 양쪽 대기실에 2명, 색·번호 다름. 참가자 쪽엔 시작 버튼 없음 |
| 2 | 움직임 확인 | 운영진이 시작 → 양쪽에서 이동/점프 | 상대가 부드럽게 움직임, 3-2-1 동안 이동 불가 |
| 3 | 탑 쌓기 | 스테이지 2에서 한 명이 서고 다른 사람이 머리 위로 점프 | 양쪽 화면에서 위 사람이 머리에 붙어 있음 |
| 4 | 20명 부하 | 주소 뒤에 `?test&bot&room=코드`를 붙여 탭 여러 개 열기(탭마다 다른 익명 사용자 + 자동 이동 봇). 탭을 각각 별도 창으로 띄워야 백그라운드 탭 속도 제한을 덜 받음. 여러 PC/폰을 섞으면 더 정확 | 20명까지 입장, 21번째는 "가득 찼어요" |
| 5 | 모바일+PC | 폰 브라우저로 같은 방 참가, 가로/세로 회전 | 가상 버튼 표시, 두 손가락 동시 입력, 회전 후 화면 맞춤 |
| 6 | 방장 이탈 | 게임 중 운영진(방장) 탭을 닫기 | 약 6~8초 뒤 남은 사람이 방장이 되고, 모두 출구에 들어가면 클리어 화면은 정상 표시. 다음 진행 버튼은 운영진이 다시 들어와야 보임 |
| 7 | 재접속 | 게임 중 새로고침 | 같은 방·같은 색으로 복귀, 체크포인트에서 시작 |
| 8 | 클리어 동기화 | 모두 출구에 들어가기 | 모든 화면에 같은 결과창, 기록 시간 동일 |
| 9 | 중복 전환 방지 | 운영진 두 명이 같은 방에서 "다음 스테이지"를 동시에 누르거나, 한 명이 빠르게 여러 번 클릭 | 스테이지가 1단계만 넘어감 |
| 10 | 사용량 | Firebase 콘솔 > Realtime Database > **사용량** 탭에서 다운로드량·동시 연결 확인. `?debug`를 붙이면 콘솔에 10초마다 보냄/받음 횟수 출력 | 아래 7장 추정치와 비교 |
| 11 | 보안 규칙 | 콘솔 규칙 탭의 **규칙 플레이그라운드**에서: 인증 안 한 읽기, 남의 `pos` 쓰기, 운영진이 아닌 uid로 `rooms/ABCDE/info` 생성, 운영진이 아닌 참가자의 `game` 쓰기, 21번째 `slots/20` 쓰기 | 모두 거부되어야 함 |

## 6. 스테이지 (모두 독자 설계)

1. 첫 걸음 — 이동·점프·열쇠·출구 학습
2. 어깨를 빌려줘 — 4칸 높이 열쇠, 친구 머리 밟기
3. 함께 누르는 스위치 — 인원수 스위치(4명 이상이면 두 곳 동시), 문 너머 스위치로 동료 호출
4. 흔들리는 발판 — 이동 발판, 체크포인트
5. 피카 탑 쌓기 — 인원 수에 따라 벽 4/5/6칸(1/2/3명 탑 필요), 벽 너머 스위치로 문 개방
6. 위와 아래 — 위층·아래층이 서로의 문을 열어 주는 역할 분담
7. 톱니 주의 — 패턴 이동 장애물, 낮은 통로
8. 무너지는 다리 — 밟으면 0.65초 뒤 붕괴, 3.6초 뒤 복구
9. 모두의 힘 — 스위치+발판+붕괴 블록+탑 쌓기
10. 피카파크 대모험 — 모든 기믹 결합

스테이지는 `game.js`의 `STAGES` 배열에 데이터로 정의되어 있어 사각형 단위로 쉽게 고치거나 추가할 수 있습니다(문자표는 코드 주석 참고).

## 7. 알려진 한계 · 요구사항 충돌과 선택

**검증한 것 / 하지 않은 것**
- 검증함: JS 문법, 규칙 JSON 형식, CDN 주소 존재, 그리고 Node에서 실제 게임 코드를 돌린 자동 테스트(픽셀 스프라이트 데이터, 10개 스테이지 × 2/4/20명 생성, 스위치 필요 인원이 항상 "인원−1" 이하, 점프 높이 59.6px로 3칸은 넘고 4칸은 못 넘음, 인원별 탑 높이 1/2/3명에서만 벽을 넘음, 발판 탑승 유지, 스위치·문 개폐, 추락→체크포인트 부활, 위치 문자열이 규칙 정규식과 일치).
- **검증하지 못함**: 실제 브라우저 렌더링, Firebase 서버와의 통신, 보안 규칙 실서버 동작, 모바일 기기, 20명 실부하. 위 5장 점검표로 꼭 확인해 주세요. 특히 보안 규칙의 `query.*` 조건(오래된 방 조회)이 거부되면 오래된 방 자동 정리만 안 되고 게임은 정상 동작합니다.

**요구사항 충돌과 선택**
- *"Phaser 물리 시스템 활용" vs "머리 위 착지가 안정적"*: Phaser Arcade 물리에 네트워크 지연이 있는 다른 플레이어 몸을 넣으면 서로 밀고 튕기는 현상이 심합니다. 그래서 **Phaser는 렌더링·카메라·텍스처**에 쓰고, 충돌은 플랫폼 게임에 맞춘 **직접 만든 AABB 충돌**(가로/세로 분리, 이미 겹친 상대는 무시)로 구현했습니다.
- *"클라이언트를 믿지 말 것" vs "서버 없이"*: GitHub Pages + Firebase만으로는 위치·클리어를 검증할 신뢰 가능한 서버가 없습니다. 보안 규칙으로 **형식·범위·권한(누가 무엇을 쓸 수 있는지)**은 막지만, 조작된 브라우저가 "출구에 들어갔다"고 보내는 것까지는 막을 수 없습니다. **완벽한 치트 방지는 불가능**하며, 이벤트 보상이 걸리면 운영진 확인을 병행하세요. 나중에 Cloud Functions(Blaze 요금제 필요)로 클리어 판정을 옮길 수 있도록 진행 상태는 `game` 한 곳에 모아 두었습니다.
- *운영진 식별*: 일반 참가자는 익명 로그인이라 기기·브라우저가 바뀌면 다른 사람으로 인식되지만, 운영진은 구글 계정이라 어디서든 같은 권한을 가집니다. 운영진 목록은 콘솔에서 직접 관리합니다(앱 안에서 운영진을 추가하는 화면은 없음).
- *관전자 입장*: 1차 버전은 진행 중 신규 참가를 막는 방식만 지원합니다.

**Firebase 무료(Spark) 한도** — 공식 가격표 기준(2026-10 확인): 동시 연결 **100개**, 저장 **1GB**, 다운로드 **월 10GB**.
- 동시 연결 100 = 20명 방이 동시에 최대 약 5개.
- 다운로드 추정(실측 아님): 20명이 모두 쉬지 않고 움직이면 위치 메시지가 1인당 초당 약 4회 × 19명에게 전달 → **시간당 약 0.5~1GB**. 멈춰 있을 때는 보내지 않으므로 실제로는 더 적습니다. 즉 20명 풀방 기준 **한 달에 대략 10~20시간** 플레이하면 무료 다운로드 한도에 닿을 수 있습니다. 소규모(2~8명)는 훨씬 여유가 있습니다.
- 한도에 가까워지면 `game.js`의 `CFG.SEND_BASE_MS`/`SEND_MAX_MS`를 늘려 줄일 수 있습니다(움직임은 덜 부드러워짐).
- Spark 요금제에는 결제 수단이 연결되지 않습니다. 한도를 넘었을 때의 정확한 동작(서비스 제한 등)은 Firebase 공식 문서와 콘솔 안내를 확인하세요. Blaze로 업그레이드하면 초과분은 과금됩니다.

**기타 한계**
- 네트워크 지연 때문에 상대 위치는 약 0.1~0.3초 늦게 보이고, 나와 상대 화면의 위치가 몇 px 다를 수 있습니다(탑 쌓기는 붙여서 보정).
- 스위치 판정은 각자의 화면 기준이라, 문이 열리고 닫히는 순간이 사람마다 아주 조금 다를 수 있습니다. 닫히는 문 안에 있던 사람은 끼이지 않고 빠져나올 수 있게 처리했습니다.
- 게임 도중 인원이 크게 줄면 스위치 필요 인원은 현재 인원에 맞춰 줄어들지만, 탑 벽 높이는 시작 인원 기준입니다. 막히면 운영진이 메뉴 > "이 스테이지 다시 시작"을 누르세요(현재 인원으로 다시 계산).
- 모바일 세로 화면은 게임이 작게 보입니다(가로 권장 안내 표시).
- 효과음은 없습니다.
